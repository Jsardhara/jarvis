## J7 — Long-running project memory

**Files:**
- `jarvis/state/projects.py` (new) — `Project` / `Milestone` / `Blocker` dataclasses, CRUD via JSONL with latest-ts-per-id wins.
- `jarvis/agent.py:_build_live_state_block` — projects block injected after facts.
- `tests/test_projects.py` (new) — 9 tests.

**What it does:** Jarvis now tracks multi-day objectives across sessions. Create a project, add milestones, log blockers, mark them done. Every chat turn pulls active projects into the system prompt so Jarvis can say "the encryption refactor is at 3/5 milestones — the AES upgrade is still blocking."

**Public API:**
```python
from jarvis.state.projects import (
    create_project, update_project, add_milestone, complete_milestone,
    add_blocker, list_projects, get_project, render_active_projects_for_prompt,
)
```

## J8 — Active proactive intelligence (LLM)

**Files:**
- `jarvis/apps/sentinel/proactive_intelligence.py` (new) — daily Sonnet pass over recent activity.
- `jarvis/apps/sentinel/routines.py` — `proactive_intelligence_tick(notifier)` calls the pass and pushes priority-0 nudges.
- `jarvis/apps/sentinel/scheduler.py` — cron at 07:30 (just before morning_digest at 08:00).
- `tests/test_proactive_intelligence.py` (new) — 5 tests.

**What it does:** beyond rule-based scanners (J3), this asks Sonnet to *find* patterns in your recent chat_turns + tasks + facts + projects and surface non-obvious connections. Examples Jarvis might generate:
- "3 of your tasks reference the Q3 deadline — draft a status update?"
- "You mentioned the encryption project yesterday, no activity since."
- "Your watchlist has overlap with this morning's BBC headline."

Dedup window: 7 days. Capped at 3 observations per pass to prevent LLM-driven spam.

## J9 — Autonomous email drafting

**Files:**
- `jarvis/state/drafted_replies.py` (new) — `DraftedReply` dataclass + append/read/update_status. JSONL store.
- `jarvis/agents/tempo/agent.py` — new `draft_replies(limit=5)` action + private `_draft_one` and `_reply_subject` helpers.
- `jarvis/apps/sentinel/routines.py` — `draft_replies_tick(tempo, notifier)` runs nightly.
- `jarvis/apps/sentinel/scheduler.py` — cron at 06:00 daily.
- `tests/test_drafted_replies.py` (new) — 4 tests.
- `tests/test_tempo_draft_replies.py` (new) — 3 tests.

**What it does:** every night at 6am, Jarvis scans recent action-required mail and drafts polite professional replies via Sonnet. Drafts queue up in `state/drafted_replies.jsonl` with `status="drafted"`. You wake up, review them, approve to send. Sending still requires authority confirmation per CLAUDE.md — `send_mail` is unchanged.

**API:**
```python
from jarvis.state.drafted_replies import read_drafts, update_status
drafts = read_drafts(status="drafted")
# user reviews, approves:
update_status(draft.id, "approved")
# tempo.send_mail then dispatches with confirmed=True
```

## J10 — Hot-mic voice with barge-in (feature-flagged)

**Files:**
- `jarvis/config.py` — `voice_hot_mic: bool = False` setting (reads `VOICE_HOT_MIC` env).
- `.env.example` — `VOICE_HOT_MIC=0` documented.
- `jarvis/apps/voice/voice_state.py` — `hot_mic_enabled` state field + setter.
- `jarvis/apps/voice/tts.py` — `interrupt()` method on TTSProvider Protocol; MockTTS/PiperTTS/ElevenLabsTTS implement it.
- `jarvis/apps/voice/silence.py` — `BargeinDetector` class (webrtcvad + energy fallback).
- `jarvis/apps/voice/loop.py` — `run_hot_mic_loop()` additive; wake-word path untouched.
- `tests/test_hot_mic.py` (new) — 4 tests.

**What it does:** **Off by default.** Set `VOICE_HOT_MIC=1` in `.env` to enable continuous listening — no wake-word needed. VAD detects speech mid-TTS and interrupts immediately so you can talk over Jarvis. EdgeTTSProvider doesn't yet implement `interrupt()` so barge-in via the default TTS stack will only suppress *future* playback, not in-flight HTTP; flagged as a follow-up. Wake-word loop is the unchanged baseline.

**To enable:**
```
# .env
VOICE_HOT_MIC=1
```

- `jarvis/skills/paper_summarize.md` (new)
- `jarvis/skills/standup_summary.md` (new)
- `jarvis/agent.py:stream()` — slash-skill dispatch after `/screen` short-circuit; new `_stream_via_skill` method mirrors `_stream_via_link_handler`.
- `tests/test_skill_library.py` (new) — 5 tests.

**What it does:** Type `/code-review` followed by your diff in the chat — Jarvis loads the code_review skill's structured prompt + agent list, runs it via the proper model, returns a focused response. 7 skills shipped covering the most common operator needs. **Usage examples:**

- `/meeting-prep with Pepper tomorrow`
- `/exam-prep CS401 final`

## What's left to reach "Iron Man JARVIS" feel

Most of the qualitative ground is now covered. What remains:

1. **Real-time interrupt-aware voice** — J10 lays the foundation but EdgeTTSProvider needs `interrupt()` to fully complete barge-in.
2. **Cross-skill orchestration** — when an answer requires running 2-3 skills in sequence, Jarvis should chain them automatically (skill-of-skills).
3. **Persistent agency** — Jarvis pursuing a goal over hours without prompting (run a backtest, monitor for X, report when done).
4. **Multi-user awareness** — single-operator today; adding "Pepper" semantics needs a contact graph.

None of these are required for the system to feel like JARVIS day-to-day. They're polish on a working foundation.
